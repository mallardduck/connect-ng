# Code Generation for SCC Registration Types

This package provides code generation for SCC registration CRD types based on `ProductConfig`.

> **Architecture Note**: This codegen produces **minimal Go source files** with the ProductRegistration wrapper type only. Your tooling (Wrangler, Kubebuilder, controller-gen) generates List types, DeepCopy methods, and CRD manifests. See [ARCHITECTURE.md](ARCHITECTURE.md) for version independence details.

> **Using Wrangler?** See [WRANGLER.md](WRANGLER.md) for simplified Rancher-specific setup.

## Single Source of Truth Pattern

The recommended approach uses your `ProductConfig` as the single source of truth - no duplicate JSON/YAML config files needed.

### 1. Define Your Product Config

```go
// pkg/scc/config.go
package scc

import "github.com/SUSE/connect-ng/k8s/productconfig"

var Config = productconfig.New(
    "rancher",       // Product identifier
    "2.10.0",        // Version
    "cattle-system", // Namespace
    productconfig.WithMetricsSecret("rancher-scc-metrics"),
    // For product variants:
    // productconfig.WithSCCProductIdentifier("rancher-prime"),
    // To customize output location (optional):
    // productconfig.WithAPIBaseDir("./pkg/apis"),  // Results in: ./pkg/apis/rancher.registration.suse.com/v1
)
```

### 2. Create a Codegen Program

```go
// cmd/generate-scc-types/main.go
package main

import (
    "github.com/SUSE/connect-ng/k8s/codegen"
    "myproduct/pkg/scc"
)

func main() {
    if err := codegen.Generate(scc.Config, nil); err != nil {
        panic(err)
    }
}
```

### 3. Run Code Generation

```bash
go run ./cmd/generate-scc-types
```

This generates CRD types in the configured output directory:
- Default: `./apis/<group>/v1` (e.g., `./apis/rancher.registration.suse.com/v1`)
- With `WithAPIBaseDir("./pkg/apis")`: `./pkg/apis/<group>/v1`
- With `WithGenerateOutputDir("./custom/path")`: exactly as specified (full control)

### 4. Run Your Codegen Tooling

After our codegen creates the ProductRegistration wrapper, use your product's tooling to generate the rest:

**Option A: Wrangler (Rancher products)**

```bash
go generate  # Wrangler generates DeepCopy, List, GroupVersion, CRDs
```

**Option B: Kubebuilder / controller-gen**

```bash
# Generate DeepCopy methods, List types, etc.
controller-gen object:headerFile=hack/boilerplate.go.txt paths=./apis/...

# Generate CRD YAML manifests
controller-gen crd:crdVersions=v1 paths=./apis/... output:crd:dir=config/crd/bases
```

**Option C: Other tooling**

Any Kubernetes codegen tool that understands kubebuilder markers will work.

**What Gets Generated**:

| File | Generated By | Purpose |
|------|-------------|---------|
| `productregistration_types.go` | Our codegen | ProductRegistration wrapper (embeds library Spec/Status) |
| `doc.go` | Our codegen | Package doc with kubebuilder markers |
| `zz_generated.deepcopy.go` | Your tooling | DeepCopy methods (controller-gen, Wrangler, etc.) |
| List types | Your tooling | ProductRegistrationList (Wrangler, Kubebuilder, etc.) |
| GroupVersion info | Your tooling | SchemeBuilder, AddToScheme, etc. |
| CRD YAML | Your tooling | Kubernetes manifests for deployment |

Our codegen only generates the minimal ProductRegistration wrapper type. Your codegen tooling (Wrangler, Kubebuilder, controller-gen) generates everything else based on the kubebuilder markers.

**Using go:generate** (Recommended):

The generated `doc.go` includes a `go:generate` directive, so you can regenerate DeepCopy with:

```bash
cd apis/<group>/v1 && go generate
```

Or from your project root:

```bash
go generate ./apis/...
```

**Why Two Steps?**

Our codegen produces version-independent Go source files. You run controller-gen with your chosen Kubernetes version to generate version-specific code. This allows different products to use different k8s versions while sharing the same library. See [ARCHITECTURE.md](ARCHITECTURE.md) for details.

## Customizing Output Location

By default, generated types go to `./apis/<group>/v1`. To customize:

**Recommended: Specify just the base API directory**
```go
var Config = productconfig.New(
    "rancher", "2.10.0", "cattle-system",
    productconfig.WithAPIBaseDir("./pkg/apis"),  // Product-specific path is added automatically
)
// Results in: ./pkg/apis/rancher.registration.suse.com/v1
```

**Advanced: Full path control**
```go
var Config = productconfig.New(
    "rancher", "2.10.0", "cattle-system",
    productconfig.WithGenerateOutputDir("./internal/apis/registration/v1"),
)
// Results in: exactly ./internal/apis/registration/v1
```

The `WithAPIBaseDir()` approach is recommended as it automatically includes the product group and version in the path, reducing duplication and potential errors.

## Why This Pattern?

**Single Source of Truth**: Your `ProductConfig` is used for both:
- Runtime configuration (`k8s.Setup()`)
- Code generation (this package)

**Type Safety**: Configuration is validated at compile time, not parse time.

**Functional Options**: Supports `WithSCCProductIdentifier()`, `WithGroup()`, etc.

**No Duplication**: No need to maintain separate JSON/YAML files that can drift from your Go config.
